# GitHub project status

The historical issue scaffold is superseded by the finding ledger in
`docs/remediation-status.md` and the current hierarchy in `issue-hierarchy.md`.

New work should be filed against one ownership boundary and one or more finding
IDs. It must include allowed files, safety invariants, positive and negative
acceptance evidence, and an explicit distinction between implementation and VM
verification. The final acceptance issue remains open until the isolated release
workflow publishes complete install/reboot/recovery evidence.
